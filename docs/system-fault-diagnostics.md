# 系统故障采集与在线查询诊断

## 用户操作

1. 在设置中开启「诊断日志」，再复现故障。
2. 闪退后重新打开应用，等待系统投递故障事件，再导出诊断日志。
3. 导出文件的 `SYSTEM FAULTS (LOCAL, FILTERED)` 部分包含已采集的记录。

未收到事件不代表没有崩溃；系统可能延迟投递、限制日志数量，或根本没有生成完整堆栈。
接入前/开启诊断前的事件不作追溯采集。不会自行上传，不新增用户权限。

## 范围与隐私

- 使用 HiAppEvent 订阅本应用 APP_CRASH、APP_FREEZE；API 20 起订阅 APP_KILLED。
- 独立本地归档，最多 6 份、保留 7 天；每个附件最多读取 512 KiB、每份保留最多 64 KiB 调用栈。
- 只保留事件类型、时间、版本、枚举化原因及代码帧。原生帧保留模块文件名、PC 和可识别的 Build ID；JS 帧保留函数、文件名和行列。
- 不复制原始异常消息、系统 hilog、内存/寄存器转储、服务器地址、完整路径或账户内容。
- 只读取系统日志目录内的普通文件；不接受目录穿越或符号链接文件。
- 关闭诊断取消订阅并清除应用归档（不删除系统自身管理的故障文件）；「清除诊断日志」也清除归档并推进采集时间边界。
- 异步串行、限量处理；订阅或读取失败不会阻断启动。

## 在线状态查询

按 query id 记录开始、地址类别、解析/连接、各并发候选结果、发送、等待响应、解码、位图校验和结束/超时。
候选仅记录索引，不记录 URL/域名/IP；错误映射为固定分类。
查询另附当前默认网络的 Wi-Fi/蜂窝/以太网类型快照，不记录 SSID；读取网络信息不会等待或阻塞查询。
DNS 和握手使用现有连接器，所以阶段为 `resolve_connect`，没有额外 DNS 探测，也不改变候选竞速、端口或超时策略。

## 定位与验收

- 原生地址还原需保留故障对应构建、架构的未剥离符号；ArkTS 混淆代码需对应 sourcemap/name mapping。
- 本改动是补证据，不代表已修复家庭 Wi-Fi 闪退。
- 回归脚本覆盖模拟系统事件、归档、脱敏、开关/清除与异步竞争；真实系统投递仍需设备复现验证。
- 不向正式应用添加主动崩溃入口，不替换系统信号处理程序。

本轮验证：34 组 CJS 回归、52 项 Windows Rust 测试通过；ARM64/x86_64 HarmonyOS 原生库编译通过。
调试 HAP 构建验证与真实设备崩溃采集验收分开，本轮未在用户设备主动制造崩溃。

参考：[官方崩溃事件订阅](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/dfx/hiappevent-watcher-crash-events-arkts.md)。
