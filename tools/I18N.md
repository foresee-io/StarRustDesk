# StarRustDesk UI languages

The default is **Follow system**. Supported languages are Simplified Chinese,
Traditional Chinese and English. Other system languages fall back to English.
The manual preference is stored locally as `ui-language`; an absent or invalid
preference means Follow system. It is not a connection or server option.

`LanguageService` sets the reactive `uiLanguage` value. Pages observe it with
`StorageLink`, so language changes do not recreate the remote page/video surface.
System permission prompts use locale-qualified resources; a manual resource
preference takes effect on the next cold start. App-owned strings update live.

`I18n.ets` is a display boundary. Protocol values, error comparisons, keyboard
codes, diagnostics, names, paths, clipboard content and messages stay unchanged.
Physical key names such as Home/Ctrl/End must not pass through the UI alias map.
For new templates, preserve all numbered placeholders. Never translate a user
name or filename independently; translate its surrounding label instead.

## Adding text

1. Add the Simplified Chinese display key and English translation to
   `i18n-en.tsv` (TAB-separated; literal `\n` for multi-line text).
2. Use `translate(sourceLabel, this.uiLanguage)` at the display boundary.
3. Generate the catalog and run tests:

```
npm install --prefix build-artifacts/i18n-tooling --no-audit --no-fund opencc-js@1.4.2
node tools/build-i18n-catalog.cjs
node tools/test-i18n.cjs
```

OpenCC is only a build-time conversion tool; the application has no runtime
dependency on it or on a translation service. Generated catalogs and resources
are checked in, so a normal app build does not require these commands.
`localize-ui.cjs` is a read-only text inventory by default. `--migrate` is a legacy
one-time migration mode and skips components already observing `uiLanguage`.

Common translations follow RustDesk's fallback approach and use a checked-in
subset of its `src/lang` dictionaries (AGPL-3.0). `i18n-common.json` records the
snapshot date and source-file hashes. Custom app text and release notes are in
`i18n-en.tsv`; generation never downloads an unpinned upstream dictionary.

Device acceptance: test Chinese/English systems, manual switches while connected,
restart persistence, system-language changes, large fonts, permission dialogs,
landscape/fullscreen, keyboard shortcuts and unchanged user filenames/messages.
